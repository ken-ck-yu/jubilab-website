Local-first metadata for scientific pipelines

Record the run.Keep the lineage.Leave the data where it is.

Jubilab is a local-first, self-hostable metadata layer for scientific data. It stores pointers and context, not your data. It runs on localhost and the server makes no outbound network calls.

It records processing runs with their inputs, parameters and versions, and shows lineage from any output back to its inputs.

01

Run it

One command starts the server, either with Docker Compose or with Python. It binds to localhost, makes no outbound network calls, and needs no AI model. Work is organised in projects, and nothing is shared between projects.

python
$ python -m server serve --data-dir ./data
jubilab: listening on http://127.0.0.1:18190 data-dir=./data
02

Record a run

Register a data asset, then a run that names it as an input, with its parameters and status. A run is history: a changed setting is a new run. Both commands below write to a local spool file.

register-asset, register-runreal session
$ jubilab register-asset --id fastq-v1 --name "Cohort_A.fastq.gz" --location s3://lab-cohort-a/fastq/ --type "FASTQ collection" --version v1
spooled register_asset key=7e094854d38fcc6ea6cc87ccae08500d -> jubilab-spool.p_8hakp36js1.jsonl

$ jubilab register-run --id run-001 --name "Variant calling, threshold 20" --input fastq-v1 -p quality_threshold=20 --status completed --executor nextflow
spooled register_run key=a685bbb34a2ad0952f877768ca06baf3 -> jubilab-spool.p_8hakp36js1.jsonl

$ jubilab register-run --id run-002 --name "Variant calling, threshold 30" --input fastq-v1 -p quality_threshold=30 --status completed --executor nextflow
spooled register_run key=ed400327f323beb1c015acf5e7ed1297 -> jubilab-spool.p_8hakp36js1.jsonl

The --location value is a pointer that Jubilab records. It does not connect to S3 or read the data; connectors are not built yet.

Lineage, backward and forward

From an output, Jubilab shows the run and the inputs that produced it, and from an input, what depends on it. Today lineage is read in the web interface; the screenshot is the demo project served by the session above.

05

On a node without internet

The CLI does not need the server to record. Each command appends to a spool file (jubilab-spool.<project>.jsonl) and returns. Later, jubilab sync sends the records, and jubilab status tells you how many are still unsynced. The spooled ... lines above are exactly what you see offline.

sync, statusreal session
$ jubilab sync
synced 3 record(s) to http://127.0.0.1:18190/api/projects/p_8hakp36js1/ingest: applied=3 duplicate=0 error=0

$ jubilab status
spool: jubilab-spool.p_8hakp36js1.jsonl (3 records, 0 unsynced)
server: http://127.0.0.1:18190 {"projects":{"active":1,"archived":0,"unavailable":0},"status":"ok","version":"0.1.0"}
project: p_8hakp36js1 (Cohort A)
06

What is a fact

Jubilab marks each fact with one of four labels instead of implying that everything is reproducible. Each is a word and a shape, not just a colour.

  • verifiedConfirmed against the thing itself.
  • inferredWorked out from other records, not observed directly.
  • manualEntered by a person.
  • unknownNot captured, and shown as unknown. The demo project has one: "Container digest not captured".
07

Ask, and get "cannot determine"

Questions are answered only from recorded evidence, with the records cited. When the records do not contain an answer, Jubilab says "cannot determine". No AI model is involved or required.

08

Limits

Jubilab is early-stage software with no customers yet.

  • Not a workflow engine. It does not run or schedule pipelines. It records runs.
  • Not storage. It holds pointers and context, never your data.
  • Not a replacement for your tools. It sits next to them.
  • No authentication yet.
  • No connectors yet for S3 or other stores.
  • No hosted service. You run it yourself.
  • Licence not decided. The product is not published.
